**Key Design Decisions:**
- **Compound Cursor**: Khi sort theo `title` (không unique), keyset pagination cần dùng `(title, id)` compound cursor thay vì chỉ `after_id`. Logic: `WHERE (title < ?x) OR (title = ?x AND id < ?y)` cho DESC.
- **Validated Fields**: Sort field được whitelist (`title`, `created_at`, `updated_at`) — không cho phép SQL injection qua sort field.
- **Filter Count**: Count query cũng áp dụng filter, nên `total` phản ánh số items sau khi lọc.

## Architecture Highlights

### Compound Keyset Cursor

```
Sort by title ASC:
  Page 1: SELECT ... ORDER BY title ASC, id ASC LIMIT 51
  Page 2: SELECT ... WHERE (title > 'Batman') OR (title = 'Batman' AND id > 42) 
           ORDER BY title ASC, id ASC LIMIT 51
```

- Tuple comparison `(sort_col, id)` đảm bảo stable order ngay cả khi sort column có giá trị trùng
- `id` luôn là tie-breaker duy nhất (monotonic, unique)
- Performance: O(1) seek thông qua compound index `(collection_id, sort_col)`

### Sort Persistence

```
localStorage:
  vaultrs-sort-field: "created_at" | "title" | "updated_at"
  vaultrs-sort-order: "ASC" | "DESC"
```

Sort preference được lưu globally (áp dụng cho mọi collection), giống UX của file manager.

### Filter Debounce Flow

```
User types → filterInput state → useDebounce(300ms) → debouncedFilter → useInfiniteItems → API call
```
